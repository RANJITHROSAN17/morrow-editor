# Morrow 0.3.0: research-informed implementation

**Status:** development candidate, not a production release. This document records what was built, why it was chosen, and what is still unverified. Research accessed 31 October 2026. Morrow has not conducted direct user interviews or a representative survey; competitor issues and online discussions are signals and hypotheses, not proof of demand among Morrow users.

## Decisions from feedback and research

| Observation | Implemented response | Important boundary |
| --- | --- | --- |
| VS Code documents adding and removing multiple folders in a workspace. Public Explorer feedback requests discoverable creation and better navigation ([VS Code docs](https://code.visualstudio.com/docs/editing/workspaces/multi-root-workspaces), [example issue](https://github.com/microsoft/vscode/issues/332105)). | Add up to 12 chosen roots; expandable tree; remove without deleting; create a file or folder explicitly; quick open and saved-file search across roots. | This is not VS Code parity: no `.code-workspace` compatibility, workspace restore, rename/delete, drag/drop moving, Git, terminal, extensions or language servers. |
| Search scope and keyboard navigation can be confusing ([example VS Code request](https://github.com/microsoft/vscode/issues/304115)); Morrow's prior usability review exposed stale results and compact-window overlap. | Name roots in multi-folder results; clear old results when search inputs change; preserve combined search limits; keep sidebar sections scrollable; fix keyboard tab closing and menu/tab arrow navigation. | Search is saved-file-only, literal and bounded; it is not a complete index or `.gitignore` implementation. |
| In Stack Overflow's 2026 survey, 48% of respondents to a trust question said they trust AI when they can easily validate answers ([survey](https://survey.stackoverflow.co/2026/ai)). | Ask or compare eligible Arena API models in the app; compare requires separate disclosure for two requests; edits require a visible review and explicit apply, then can be undone. | Survey respondents are not Morrow users. AI output may be wrong or unsafe. Compare is not Arena website voting or blind battles. |
| Arena documents an OpenAI-compatible API endpoint and separately notes free-router key restrictions ([OpenCode setup](https://platform.arena.ai/docs/opencode), [Claude Code setup](https://platform.arena.ai/docs/claude-code)). | Bring your own eligible key and model; display costs/entitlements and data destination; website flow remains external. | Arena website login does not grant Morrow API access. Free-router keys may be restricted. No successful authenticated Morrow request has yet been verified. |
| OWASP identifies prompt injection, disclosure, improper output handling, excessive agency and unbounded consumption as LLM application risks ([OWASP](https://genai.owasp.org/llm-top-10/)). | Per-request consent; bounded input/output/time; fixed endpoint and no redirects; output rendered as inert text; no shell/tool access; no automatic edits; model responses require review before applying. | These measures reduce specific risks, not a guarantee against prompt injection, incorrect answers, provider retention or all attacks. The key is held in application memory, not an OS credential vault. |
| The Windows Server 2025 GUI review recorded a new-file save failure with an empty `x-morrow-expected` header. | Use a nonempty `absent` sentinel; strictly validate metadata on both sides; do not overwrite a new/different destination without a separate explicit confirmation; use no-clobber creation; retain hash conflict checks. | Empty-header transport was a likely cause, not a proven WebView2 root cause. Existing-file checks retain a final filesystem race. The changed path still needs packaged Windows testing. |

## Safety boundaries and trade-offs

- Morrow does not auto-run project contents, commands, extensions, language servers or Arena responses. Directory and search content is untrusted text.
- User-selected desktop folders grant recursive Tauri file-access scope, which the persisted-scope plugin may keep after a folder is removed from the workspace or Morrow restarts. Removing a root is not permission revocation. All active workspace roots are session-only.
- Native folder creation validates names and selected-root containment, rejects detected reparse points and uses exclusive creation for the last component. Parent-directory races and platform/filesystem quirks are not completely eliminated. Browser File System Access lacks an exclusive-create primitive; it does not truncate an existing file but can return a file another process created after the check.
- The Arena panel sends the question/instruction, optional selected text and a fixed task instruction to Arena and its model providers. The local secret warning is incomplete and can produce false positives. No account- or provider-level confidentiality, retention or model quality is guaranteed.
- Arena results are independent requests without conversation history. Their contents are displayed as text, not HTML; edits target a captured, revision-checked range, are applied literally, and do not save automatically. Comparing sends the same submitted content in two distinct calls.
- Session recovery remains local, unencrypted and best-effort; it is not a backup. Ollama at loopback may route to cloud models. Existing save conflict checks are not file locks or transactional guarantees.

## Validation and remaining release gates

Local validation on 31 October 2026 passed a production frontend build, **64 TypeScript unit tests**, **41 Chromium/Playwright tests**, and **11 Linux Rust tests**. The UI suite includes mocked desktop IPC for per-send consent, two-model comparison and reviewed undo; browser tests cover multi-root navigation, creation, search invalidation, keyboard and compact layout. Rust tests cover save metadata, no-clobber behavior, traversal/link checks and window geometry. The production npm audit reported no vulnerabilities at moderate or above; that result is not a security audit. The frontend build reports a greater-than-500 kB chunk warning.

A separate synthetic GUI smoke check ran the candidate as a **Linux Tauri development build** (WebKitGTK, virtual 1024×768 display): a new note saved with exact expected text; an external disk edit triggered the conflict dialog without overwriting it; two real selected folders were browsed; a file was created and saved; an existing filename collision preserved its contents; and saved-file search returned one match from each root.

The packaged, unsigned 0.3.0 x64 candidate was also built and installed on a **GitHub-hosted Windows Server 2025 VM** (build 26100, 1024×768 display). Its Windows build passed 64 unit, 41 browser and 9 Windows Rust tests. A scripted Windows-MCP GUI run with synthetic files verified exact new-file save bytes, an external-edit conflict without overwriting, two selected roots and cross-root search, creation and save, an existing-name collision preserving original bytes, initial fit within the work area, and the Settings button at a requested 720×500 window size. The Arena panel was opened but no real key or API request was used. This is a targeted smoke test, not autonomous testing, a security audit or proof of compatibility with Windows 10/11. Screenshots, scripts and logs are in the local `Morrow-0.3.0-Windows-QA` evidence folder; the temporary public testing branch is intended to be deleted afterward. Mocks do not demonstrate a successful authenticated Arena request.

Before describing a Windows installer as release-ready, run the current packaged candidate on Windows, verify exact saved bytes for new files and Save As, test external changes, same/different destinations, creation/collisions, folder access and window behavior at multiple resolutions and DPIs. The previous GUI review used Windows Server 2025, not Windows 10/11. Independently verify an eligible authenticated Arena request; audit privacy and security; perform screen-reader/keyboard and high-contrast checks; evaluate installer signing, dependency advisories and reproducible performance. Do not claim a full security audit, accessibility conformance, free API access, feature parity or speed superiority without those checks.
